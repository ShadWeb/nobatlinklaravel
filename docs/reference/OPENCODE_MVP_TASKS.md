## قرارداد مشترک داده و API — مبنای پیاده‌سازی

پیش از اجرای تسک ۱.۲، نسخه نهایی این قرارداد را در docs/MVP_API.md ثبت کن. اگر میزبان مسیر را تغییر می‌دهد، فقط سازوکار اجرا را عوض کن؛ قرارداد UI و نام مفهوم‌ها ثابت بماند.

مدل حداقلی:

- User: id، phoneNormalized یکتا، platformRole(user/platform_admin)، createdAt. مالک‌بودن از رابطه Business مشخص می‌شود و یک کاربر می‌تواند مشتری هم باشد.
- Session: tokenHash، userId، expiresAt. OtpChallenge: id، phoneNormalized، purpose، codeHash، expiresAt، attemptCount، consumedAt، resendAfter؛ محدودیت ارسال پایدار بین درخواست‌ها/instanceها.
- Business: id، ownerId یکتا، slug یکتا، name، category، categoryLabel اختیاری، description، publicPhone، address اختیاری، imageKey، galleryKeys حداکثر۶، themePreset، timezone=Asia/Tehran، publicationStatus(draft/published)، suspendedAt اختیاری. مالک اجازه رفع تعلیق خودش را ندارد.
- Service: id، businessId، name، durationMinutes، priceToman به صورت integer، active، description. زمان و قیمت رزرو به صورت snapshot نگهداری شوند.
- WorkingHours: businessId، weekday، startMinute، endMinute، breakStart/End اختیاری؛ Closure: businessId، localDate. مرجع weekday و تبدیل به شمسی را مستند کن؛ UI شمسی، تاریخ قراردادی ISO باشد.
- Booking: id، businessId، serviceId، customerUserId اختیاری فقط برای ثبت دستی، name، phoneSnapshot، startsAt/endsAt UTC، serviceName/duration/price snapshot، status(confirmed/cancelled)، source(online/manual)، idempotencyKey، createdAt/cancelledAt. پرداخت در نسخه اول ندارد.

API پیشنهادی قطعی برای شروع (پیاده‌سازی معادل با Server Actions فقط با ثبت نگاشت روشن مجاز):

| روش/مسیر | دسترسی و رفتار |
| --- | --- |
| POST /api/auth/otp/request | phone + purpose؛ پاسخ challengeId، expiresAt، resendAt؛ در خطای سرویس نشست نساز |
| POST /api/auth/otp/verify | challengeId + code؛ cookie نشست؛ شماره از challenge معتبر |
| GET /api/auth/me ؛ POST /api/auth/logout | کاربر فعلی/خروج؛ عدم نشست پاسخ روشن 401 |
| GET/POST /api/businesses | کسب‌وکار مالک فعلی/ایجاد draft؛ ownerId از نشست |
| GET/PATCH /api/businesses/{id} | فقط مالک یا عملیات صریح مدیر؛ payload سفیدفهرست، نقش/تعلیق قابل mass-assign نیست |
| GET /api/businesses/check-slug?slug=... | برای مالک؛ نتیجه کمکی، constraint DB مرجع نهایی |
| PUT /api/businesses/{id}/services ؛ PUT .../schedule | فقط مالک؛ اعتبارسنجی فیلد و مالکیت serviceId |
| POST /api/businesses/{id}/images | فقط مالک، multipart و اعتبارسنجی واقعی فایل |
| POST /api/businesses/{id}/publish | اعتبارسنجی حداقل خدمت، ساعات و اطلاعات الزامی |
| GET /api/public/businesses/{slug} | فقط داده عمومی published و غیرمعلق |
| GET /api/public/businesses/{slug}/availability?serviceId=...&date=YYYY-MM-DD | مدت و تعلق خدمت از DB؛ زمان‌های قابل رزرو |
| POST /api/bookings | مشتری با نشست؛ business/service/date/time/name + idempotency key؛ phone از نشست |
| GET /api/bookings/mine?businessId=... | فقط رزروهای کاربر نشست در همان کسب‌وکار |
| GET /api/bookings/{id} ؛ POST .../{id}/cancel | فقط مشتری صاحب نوبت یا مالک همان کسب‌وکار |
| GET/POST /api/businesses/{id}/bookings | مالک؛ فهرست تاریخ/جست‌وجو و ثبت دستی |
| GET /api/admin/businesses ؛ PATCH /api/admin/businesses/{id}/status | فقط platform_admin؛ فعال/تعلیق |

موفقیت: {data: ...}. خطا: {error:{code,message,fieldErrors?}} با HTTP صحیح. 400 داده نامعتبر، 401 بی‌نشست، 403 بدون مجوز، 404 ناموجود/داده خصوصی نامجاز طبق سیاست ثابت، 409 تداخل/تکرار، 429 محدودیت و 503 سرویس در دسترس نیست. هیچ پاسخ عمومی hash/کد/نشست یا اطلاعات مشتریان را ندهد. صفحات خصوصی و API نشست/نوبت cache عمومی نشوند؛ جلوگیری از cache leak در نسخه فعلی Next را از مستندات نصب‌شده بررسی کن.
